Open work for this project. Cross-cutting / multi-project initiatives live in the
workspace root `TASKS.md`. Completed items are not archived here — git history is the record.

- [ ] **Keras family: the registration gap the torch family closed on 2026-08-24** @low @framework — `matrainer.cli.register_frameworks` imports a registration module only when the framework is named on ARGV, so a keras run materialized outside the CLI flag path (`recordstream run cfg.yaml --framework keras`, or a config whose `default_scopes:` names keras) imports `sonair.keras_classification` never — bare registered names fail and the manifest's `final.yaml` dumps the keras losses/metrics as opaque placeholders. The torch family fixed this with a load-bearing import in the shared hooks module (`classification_torch.py` imports `torch_classification` — see AGENTS.md); `keras_classifier.py` has no such edge (it names `keras_classification` only in a docstring, `keras_classifier.py:72`). Apply the same pattern when a keras run in that shape actually matters; decide then whether the keras `**kwargs` metric classes also want `broadcast="declared"`.

- [ ] **Multi-label predictions sink** @feature — `recordstream.predictions.ClassificationPredictionsSink` (`recordstream/predictions.py:53`) records the top-k classes of one softmax per record (`top_k`; `confidence_threshold` filters on the top-1 probability only), and `recordstream.outputs.classification_output` (`recordstream/outputs.py:129-131`) builds `probs` with a softmax and `class_idx` with an argmax even for a multi-label run — the wrong shape for multi-label inference (every class over a per-class threshold, count unknown). Needs a per-class threshold on the sink and a decision on how a multi-label run's `probs` is defined. Multi-label training and evaluation are built; only the predict-side sink is open.
- [ ] **Give `huggingface` training metrics behind an opt-in knob** @low — the ONE blank pair in the sweep's table (`train/accuracy` / `train/f1_macro`). `compute_metrics` is a `transformers.Trainer`'s EVALUATION hook, so the only route is an epoch-end `TrainerCallback` calling `trainer.evaluate(train_set, metric_key_prefix="train")` — a second forward pass over the whole train split every epoch. Deliberately NOT paid by default (user decision 2026-08-04); if it lands it must be a `train_metrics` slot that is off unless wired, and `tests/test_metric_slots.py::SERVED` + the per-split mandate move `huggingface` into the union group in the same change.
