- [ ] **A DataLoader WORKER that is first to materialize a HuggingFace split segfaults on macOS** @medium @bug @cross-project — DIAGNOSED 2026-08-02; what is open is which layer owns the fix. Symptom: the fastai and huggingface cells of `examples/sweep/run_sweep.sh` die in ~11-29s with `DataLoader worker exited unexpectedly`, while lightning / torch / keras / tensorflow run the SAME config (`num_workers: 8`) fine. **The child dies of SIGSEGV in `_scproxy.get_proxies` -> `SCDynamicStoreCopyProxiesWithOptions` -> CoreFoundation `_CFXPreferences`** — read from the macOS crash reports in `~/Library/Logs/DiagnosticReports/`, twice, with identical stacks (the real fastai failure and a minimal repro). That is CPython's macOS system-proxy lookup, which `urllib.request.getproxies()` calls and which is not safe in that child process. It is reached because the worker is the FIRST process to materialize the split — the log line immediately before every crash is `HuggingFaceSource: Loading mnist (test)...` — so the HuggingFace hub client is constructed there and checks proxies. **Three remedies, each measured to pass:** `HF_HUB_OFFLINE=1` (no hub call, so no proxy lookup), ONE real record read of the split in the parent before `fit()` (`ensure_record_dataset(val_set)[0]`), and `num_workers: 0`. **`len()` in the parent is NOT enough** — measured, still crashes — so the fix has to be an actual read, not just loading the dataset object. **Two earlier guesses were WRONG and are recorded so they are not re-tried:** it is not a pickling failure (`pickle.dumps(clf._to_tuple)` succeeds), and it is not about `fork` — the default start method is `spawn` (an earlier reading of `fork` came from an import context where fastai had already set it), which also kills the bound-method-collate correlation, since the passing backends use the same worker machinery. What is undecided: whether the fix belongs in recordstream (a source that builds a network client on first read is a hazard for ANY worker-based consumer), in the two sonair backends (materialize in the parent, as the others happen to), or in the sweep script (`HF_HUB_OFFLINE`).
