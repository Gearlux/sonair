# sonair — backlog

Open work for this project. Cross-cutting / multi-project initiatives live in the
workspace root `TASKS.md`. Completed items are not archived here — git history is the record.

- [ ] **StreamStudio: framework-aware object sockets.** confluid 0.3.0 ships the `framework` axis and navigaitor filters slot options by it, but StreamStudio still lets any `RECORDSTREAM_OBJECT:model` dock into any model slot regardless of engine. Qualifying the socket type (`…:model:torch`) is a BREAKING workflow-format change — ComfyUI enforces socket compatibility by string equality and persists the strings in saved `workflow.json` — so it needs its own decision + a migration story. Until then a canvas can still wire a torch loss into a Keras trainer. See `docs/architecture.md` §2. @medium @architecture
- [ ] Implement the `jax` / `huggingface` / `mlx` backends (templates registered; each is one row moved from `TEMPLATES` to `IMPLEMENTED` in `cli.py` plus a runnable). @low @framework
- [ ] **Extract the engine-neutral half of `initialize()`** @medium @refactor — the target peek -> multilabel flag -> `LabelMap` fit/encode -> `num_classes` -> `class_names` sequence now exists in THREE near-identical copies: `LightningClassifier._initialize_fit` (plus balancing and metric collections), `KerasClassifier._initialize_fit` (which `TensorFlowClassifier` inherits) and `FastaiClassifier._initialize_fit`. None of it is engine-specific. It was duplicated rather than extracted when the fastai backend landed (2026-07-30) to keep that change reviewable and to avoid refactoring a verified backend as a rider on a feature; a fourth copy is the signal to do it properly. Any extraction must keep `KerasClassifier` the base `TensorFlowClassifier` subclasses.
- [ ] **`marainer.fastai` tracking callback** @medium @cross-project — every other backend forwards PER-EPOCH metrics to marainer trackers (`marainer.lightning.TrackingCallback`, `marainer.keras.keras_tracking_callback`); the fastai backend currently writes only the end-of-run artifacts (`save_class_names` + `write_metrics_sidecar`) and passes wired fastai `Callback`s through the `logger:` slot. The missing piece is a `fastai.callback.core.Callback` that forwards `learn.recorder` values, and it belongs in **marainer**, not sonair (the "generic primitives live upstream" mandate) — so it is a marainer task with a one-line sonair follow-up in `_callbacks()`.
- [ ] **Drop the `[fastai]` upper bounds when upstream fixes them** @low @dependency — `fastcore<2` and `fastprogress<1.1` are documented in `pyproject.toml` with the exact symptom each prevents. Recheck by removing one bound and running `sonair fastai train`: `fastcore` is clear when `Learner.fit_one_cycle` no longer dies in `Optimizer.set_hypers` (fastai restoring `L.starmap` or dropping the call); `fastprogress` is clear when 1.1+ stops depending on `python-fasthtml`, or when nothing else in the workspace pins `starlette` below what it wants.
